# План реализации MJL

## Текущий этап — инфраструктурный каркас
- [x] TypeScript + Node.js
- [x] grammY Telegram bot
- [x] Vercel serverless webhook и проверка secret token
- [x] Supabase client (server-only service role)
- [x] SQL-схема основных сущностей
- [x] Проверка административного доступа по Telegram ID
- [x] Базовое меню клиента и чтение каталога
- [x] Базовые unit-тесты форматирования

## Ещё не реализовано
- [ ] Полный CRUD товаров и категорий
- [ ] Мастер создания/редактирования товара с фотографиями, черновиком и предпросмотром
- [ ] Оформление заказа, сбор контактов, проверка и резервирование остатков
- [ ] Управление статусами заказов и уведомления
- [ ] Публикация/редактирование/архивирование постов канала и сохранение message_id
- [ ] Создание и анализ Telegram-опросов
- [ ] Кампании, аналитика, CSV/XLSX экспорт
- [ ] Роли администраторов и расширенный аудит
- [ ] Интеграционные тесты и end-to-end проверка

## Правила выпуска
1. Не публиковать товар с неподтверждёнными ценой, характеристиками или наличием.
2. Не хранить секреты в Git; использовать Vercel Environment Variables.
3. Не считать функциональность готовой до проверки реального Telegram webhook и Supabase.
4. Перед включением заказов обеспечить идемпотентность, серверную валидацию и атомарную проверку остатков.
5. Любая административная операция должна проверять Telegram ID на сервере и записываться в журнал аудита.
